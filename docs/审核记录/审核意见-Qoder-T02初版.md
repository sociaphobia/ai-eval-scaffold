### 重要（T02 完成门禁，须修正）

**重-1 默认校验错误破坏统一错误契约。** `app/main.py:17-22` 仅注册了 `AppError` 处理器。凡进入 FastAPI 自身校验或路由失败的请求，返回 `422 {"detail":[...]}` 或 `404 {"detail":"Not Found"}`，与架构:176“错误响应统一为 `{code,message,issues}`”及架构:180“未知路径 → 404 `not_found`”不符。最小复现（可证）：① `POST /api/v1/projects` 体为 `json="x"`（非 dict）→ 422 detail 结构；② 导入请求缺 `file` 字段（batches.py:33、:40 的 `File(...)`）→ 422 detail 结构；③ `GET /api/v1/unknown` → 404 detail 结构（`web/dist` 不存在时）。影响：前端问题清单（T05）在这些路径拿不到中文 `message`。修正：为 `RequestValidationError` 与 `StarletteHTTPException` 增加统一映射处理器。

**重-2 开发计划明定的 T02 自测项缺失，回归门禁无防护。** `开发计划.md:86` 把下列项写入 T02 完成定义，但四个测试文件中无任何对应用例：① 回归导入无基线 409（imports.py:106-108）；② 部分重合与完全无交集整批零写入、无交集返回“请先建立新用例基线”提示（imports.py:117-120）；③ 依据摘要排除 `version_label`/`answer`/文件顺序、包含输入与要点顺序（imports.py:90-96）；④ 超长（>256）标识与缺字段拒绝。这些是本次新增代码路径（imports.py:99-148），日后重构若被无意放宽（如把集合相等改成子集判断）不会有任何测试变红，属“遗漏导致错误放行”的真实风险。修正：可在仓储层手工插入 `baseline_events` + `current_baseline_id` 后走 API 断言，无须等 T03。

**重-3 生产方证据与工作区不符。** 报告称 `15 passed`（审核任务:8），但当前工作区四个指定文件的测试函数实测计数为 14（test_imports.py 7 个、test_rules.py 2 个、test_repository.py 1 个、test_smoke.py 4 个；无 `tests/conftest.py`，`pyproject.toml` 无参数化配置）。本审核未独立运行，仅指出数目矛盾：要么命令输出来自含已删用例的旧版本，要么统计有误。须以当前工作区重跑并回报实际数字。
