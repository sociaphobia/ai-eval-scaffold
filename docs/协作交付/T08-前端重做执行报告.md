## 4. 构建方案说明（为何不是 vite build）

沙箱禁止以管道 stdio 派生子进程。esbuild 的 transform/build 服务均以管道 stdio 派生服务进程且导出 getter 不可重定义，标准 vite build 在本环境整体不可用。`build-check.mjs` 用零管道链路产出语义一致的产物：

1. `tsc --project tsconfig.build.json`（继承 stdio，可用）把 TSX 转译为 JS + Automatic JSX Runtime；
2. rollup 3 打包。react/react-dom/scheduler 是 CJS 且 @rollup/plugin-commonjs 未安装，改为**按文件键内联 CJS 注册表**：构建期把包分发器与 `cjs/*.production.js` 实现源码内联进 bundle，require 调用在源码层重写为注册表查表；构建期用同一份运行时源码在 VM 求值取真实导出键生成 ESM 出口包装，保证构建期键与运行时键一致；
3. postcss 编译两份样式表；入口 HTML 手工组装（与 vite 语义一致）。

**白屏修复记录**：第一版打包产物在 Node 探针里自测通过但浏览器白屏——根因是 bundle 内残留运行时 `require("react")`（Node 有 require、浏览器 ESM 没有，React 未挂载）。重写为内联注册表后，本轮在真实浏览器中验证：页面正常挂载、全部交互可用（第 3 节）。

3. **沙箱内浏览器进程三条路径均不可用**（留痕）：① Playwright Runner worker 派生 → EPERM；② Node 直接 spawn `msedge.exe --version` → EPERM；③ pwsh `Start-Process` 启动的 Edge 可达进程创建（stderr 曾出现 `DevTools listening`），但随后必死于 `FATAL:mojo\public\cpp\platform\platform_channel.cc:183 拒绝访问 (0x5)`——含 `--headless`、`--single-process`、全新 profile 在内的 30+ 次连续重试无一存活。DSH 侧边栏浏览器无自动化接口（官方文档明确「不注册工具」，全机监听端口无 CDP）。本轮改用 harness 托管的 MCP 浏览器完成真实浏览器验证。
