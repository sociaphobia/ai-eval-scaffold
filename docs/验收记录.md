## 数据库恢复判定

当前 `app/repository/sqlite.py:69-82` 没有开启 WAL，每个应用连接退出时提交并关闭。恢复演练先结束所有数据库调用，再复制 SQLite 主文件到隔离目标；恢复后检查底层完整性、外键和当前已接纳基线的业务资格。`scripts/核验数据库.py` 是只读核验入口：数据库不存在时返回退出码 `2`，不会新建空库；核验失败返回非零，项目方应保持服务停止。

SQLite 官方资料：

- [SQLite WAL 文档](https://www.sqlite.org/wal.html)：默认日志模式为回滚日志；改用 WAL 后，`-wal` 文件可能包含数据库持久状态，不能把它与主数据库分开复制。
- [SQLite 在线备份 API](https://www.sqlite.org/backup.html)：在线备份可由 SQLite Backup API 生成一致快照；当前演练按停服复制单文件执行。
- [SQLite PRAGMA 文档](https://www.sqlite.org/pragma.html)：`integrity_check` 不代替外键核验，因此恢复脚本另外运行 `foreign_key_check`；两者仍不代替项目级基线资格校验。

## 已知警告与未完成事项

- 本机 npm 用户配置含 `electron_mirror` 与 `electron_builder_binaries_mirror` 两个未知配置项；npm 提示它们未来会停止受支持。它们不影响本轮测试和构建退出码。
- 初次在本机系统临时目录构建时，esbuild 清理临时目录返回 `Access is denied`；将当前构建进程的 `TMP`、`TEMP` 指向已忽略的 `data/build-temp/` 后，前端构建退出码为 `0`。这是本机临时目录权限差异，不是前端编译错误。
- Playwright 依赖安装时 npm 提示 `esbuild` 安装脚本尚未加入本机 `allowScripts` 白名单；本轮 `test:e2e` 与生产构建均实际通过，没有修改该用户级安全配置。
- 当前生产构建的 JS 分块为 647.02 kB，超过 Vite 500 kB 提示阈值。本轮功能验证通过；代码拆分属于后续性能优化，不作为业务功能通过证据。
- 项目方真实五类样例尚未提供，因此误报／漏报比例、规则覆盖率或实际业务效果均未验证。
- SQLite 官方 WAL 说明仍是重要维护约束；若将来启用 WAL，须先实现 WAL 兼容的在线备份或停服检查策略，并补充恢复演练。

## 决策依据

- 增加固定版本 `@playwright/test` 是为了使开发计划 T06 要求的真实浏览器端到端流程可重复运行；该依赖只用于开发验收。
- 增加 `scripts/核验数据库.py` 是为了把当前恢复演练中的只读完整性、外键和基线资格核验做成项目方可直接运行的步骤。它不会创建数据库、迁移数据或改变恢复文件。
- 运行期网络验收用真实浏览器捕获请求与响应；数据库恢复与资格检查直接使用本项目 SQLite 和资格核验实现；测试夹具仍明确标为自造。
- 首次直接运行核验脚本时发现脚本目录未包含项目根目录，导致 `ModuleNotFoundError: app`；将项目根目录放入该只读工具的模块搜索路径后，真实隔离数据库核验与“缺失文件不得创建”检查均通过。
- Qoder 首轮固定 20 项哈希审核判“接受”，记录见 [Qoder 首轮审核意见](审核记录/审核意见-Qoder-T06第一轮.md)。按审核意见把网络证据限定为 URL origin、使 E2E 从运行期数据直接生成请求日志和截图，并清理本轮唯一隔离数据库。清理安排依据 [Playwright 官方测试配置文档](https://playwright.dev/docs/api/class-testconfig)的配置元数据和 afterAll 钩子能力；仅清理 Playwright 本轮记录的确切数据库路径及 SQLite 辅助文件。
