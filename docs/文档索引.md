## 三、历史审核证据入口（[`docs/审核记录/`](审核记录/)）

按整理映射归档后，历史审核链条全部集中于该目录；文件保持原名与原文，逐文件绑定其审核时的冻结哈希。该目录是计划中的归档位置，落地前在项目实际目录中不存在。

| 类别 | 命名规律 | 说明 |
| --- | --- | --- |
| 审核任务单 | `审核任务-<审核方>-<对象><轮次>.md` | 各轮只读审核的任务与冻结清单，含未执行成功或中断的单据 |
| 审核报告 | `审核意见-<审核方>-<对象><轮次>.md` | Qoder、Luna、ZCode、CodeBuddy 与第 1-3 轮的历史判定原文 |
| 审核处理 | `审核处理-<对象>.md` | 生产方对逐条意见的处理登记 |
| 审核补充 | `审核补充-<来源>-<对象>.md` | 同批次补发与逐条核对材料 |
| 审核清单 | `审核清单-Qoder-T04.json` | T04 哈希审核清单 |

对象覆盖：需求草案 0.11-0.19 与 1.0 定稿链、架构 0.1-1.0、开发计划 0.1-0.2、T02-T07 各任务，以及 T06/T07 系列（原在 `docs/` 根下，一并归档）。

按旧名定位（历史正文与交接记录里写的仍是旧路径）：

- 旧位置在项目根的一批 `审核任务-*.md`、`审核意见-*.md`、`审核处理-*.md`、`审核补充-*.md` 与 `审核清单-Qoder-T04.json`，落地后在 `docs/审核记录/` 下同名存在。
- 旧位置在 `docs/` 根下的 `审核意见-Qoder-T06第一轮.md`、`审核意见-Qoder-T06第二轮.md`、`审核意见-Qoder-T06第四轮.md`、`审核意见-Qoder-T07-前端视觉改版.md`、`审核任务-Qoder-T07-前端视觉改版*.md` 等，同样在 `docs/审核记录/` 下同名存在。
- 逐条旧路径到新路径的对照与理由见 [协作交付/整理-20260929/草稿/整理映射.json](协作交付/整理-20260929/草稿/整理映射.json)。映射文件留在草稿目录作为本次归档审计依据，没有复制到其他位置；归档已于 2026-09-30 完成。

## 五、使用约定

- 判断“当前状态”只读第一节权威文件与 [HANDOFF.md](../HANDOFF.md)；`docs/审核记录/` 内一切结论均为其绑定版本的历史证据，不得当作当前通过结论。
- 历史哈希台账与各审核报告中的 SHA-256 记录其当时版本；2026-09-30 整理落地后的归档与覆盖文件哈希见 docs/协作交付/整理-20260929/落地后文件哈希.json。
- 本项目不接入金融项目；架构中引用的金融项目代码出处仅为只读技术参照记录。
